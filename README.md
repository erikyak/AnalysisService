# Инструмент для анализа файлов

## Описание

Данное веб-приложение позволяет загружать текстовые файлы в формате .txt, выполнять их анализ (подсчет количества абзацев, слов и символов) и генерировать облако слов с использованием внешнего API. Приложение построено на микросервисной архитектуре с использованием Python и FastAPI

## Архитектура

Система состоит из трех основных микросервисов:

1. API Gateway: Точка входа для всех клиентских запросов, отвечает за маршрутизацию запросов к соответствующим микросервисам.
2. File Storing Service: Управляет загрузкой и хранением файлов. Вычисляет хеш файла для проверки дубликатов, сохраняет метаданные в базе данных и содержимое файлов в локальном хранилище.
3. File Analysis Service: Выполняет анализ текстовых файлов, включая подсчет абзацев, слов, символов и частотности слов, а также генерирует облако слов с использованием внешнего API. Результаты анализа сохраняются в отдельной базе данных, а изображения облаков слов — в локальном хранилище.

## Компоненты системы

- API Gateway: Маршрутизирует запросы к File Storing Service и File Analysis Service.
- File Storing Service:
  - База данных PostgreSQL для хранения метаданных файлов
  - Локальное хранилище для содержимого файлов
- File Analysis Service:
  - База данных PostgreSQL для хранения результатов анализа
  - Локальное хранилище для изображений облаков слов
  - Внешний API QuickChart для генерации облаков слов

## Установка

Для настройки и запуска проекта выполните следующие шаги:

1. Клонирование репозитория:
   ```
   git clone
   cd AnalysisService
   ```
   
2. Сборка и запуск сервисов:
   ```
   docker-compose up --build
   ```
## Использование

Приложение предоставляет следующие API-эндпоинты:

1. Загрузка файла:
   - Эндпоинт: `POST /files/`
   - Ответ: JSON с идентификатором файла (`file_id`).

2. Анализ файла:
   - Эндпоинт: `POST /analyze/{file_id}`
   - Ответ: JSON с результатами анализа, включая количество абзацев, слов, символов, частотный словарь и URL изображения облака слов.

3. Получение результатов анализа:
   - Эндпоинт: `GET /analyze/{file_id}`
   - Ответ: JSON с кэшированными результатами анализа.

4. Получение изображения облака слов:
   - Эндпоинт: `GET /analyze/{file_id}/image`
   - Ответ: Изображение в формате PNG.

## Документация API

Документация API доступна через Swagger UI по адресу `http://localhost:8000/docs` для API Gateway. Аналогично, каждый микросервис имеет собственный Swagger UI по соответствующим портам (`http://localhost:8001/docs` для File Storing Service и `http://localhost:8002/docs` для File Analysis Service).

## Микросервисы

1. API Gateway:
   - Отвечает за маршрутизацию запросов
   - Обрабатывает клиентские запросы и ответы

2. File Storing Service:
   - Управляет загрузкой и хранением файлов
   - Сохраняет метаданные в PostgreSQL (таблица `files`)
   - Сохраняет содержимое файлов в локальном хранилище

3. File Analysis Service:
   - Анализирует текстовые файлы, подсчитывая абзацы, слова, символы и частотность слов
   - Генерирует облако слов через внешний API QuickChart
   - Кэширует результаты анализа в PostgreSQL (таблица `analysis`) для предотвращения повторных вычислений.
   - Сохраняет изображения облаков слов в локальном хранилище

## Взаимодействие между сервисами

- API Gateway общается с File Storing Service и File Analysis Service через HTTP-запросы.
- File Analysis Service запрашивает содержимое файлов у File Storing Service для выполнения анализа.

## Внешние зависимости

- QuickChart Word Cloud API: Используется File Analysis Service для генерации изображений облаков слов.
